# Programs whose native behaviour is known to differ from Node. One program name per
# line; `#` starts a comment. Every entry is explained, with a reproducer, in
# docs/wp13-differential.md ("Discrepancies"). The runner reports these as KNOWN and
# does not fail on them; a listed program that starts to agree is reported as XPASS.
#
# Regenerate from the current results with: node tests/differential/run.js --update-known

# By design (documented in docs/wp7-runtime.md and README.md)
corpus/f64_libm            # glibc libm vs V8 fdlibm: 1-ulp differences in sin/cos/log/pow

# By design (Rust semantics): integer division checks its divisor and panics with exit 1
corpus/int_div_overflow    # INT_MIN / -1: "attempt to divide with overflow"; JS gives INT_MIN
corpus/int_div_zero        # x / 0, x % 0: "attempt to divide by zero"; JS gives 0 after | 0
cases/div_zero_panic       # 10 / 0 panics (exit 1); JS gives 0 after | 0
cases/u_div_zero_panic     # u32 / 0 panics too (one compare instead of two); JS gives Infinity >>> 0
cases/div_overflow_panic   # INT_MIN % -1 panics (exit 1); JS gives 0
# By design (Rust semantics): signed `+ - *` that leaves its type panics with exit 1;
# the frozen rewrites wrap with `| 0` and `Math.imul`, as the language did before
corpus/arr_2d              # an i32 matrix product past INT_MAX: "attempt to multiply with overflow"
corpus/f64_i32_mixed       # an i32 product past INT_MAX: "attempt to multiply with overflow"
corpus/modules_basic       # math.ts's cube past INT_MAX: "attempt to multiply with overflow"
corpus/parse_argv_sum      # `ints += p` past INT_MAX: "attempt to add with overflow"
corpus/str_large           # an i32 sum past INT_MAX: "attempt to add with overflow"
corpus/str_template        # `2147483647 + 1`: "attempt to add with overflow"
# By design (WP31 §6): a value leaving `integer<Lo, Hi>` at an entry panics with exit 1;
# under Node the type is a `number` alias and nothing is checked
cases/rng_entry_panic      # the last i++ leaves integer<0, 255> (exit 1); JS finishes the loop
cases/rng_entry_panic_f64  # the same program in f64 mode, which the unmodified runner compares
cases/rng_entry_range_panic   # -3 of integer<-5, 5> enters integer<0, 9> (exit 1); JS passes it on
cases/rng_entry_push_panic    # push(12) onto integer<0, 9>[] through a field (exit 1); JS pushes it
cases/rng_entry_bitwise_panic # 7 <<= 3 leaves integer<0, 15> (exit 1); JS prints 56
cases/perf_rng_counter        # WP31 §8: the warned counter's last i++ leaves integer<0, 255> (exit 1); JS prints 32640

# Native-only introspection: these print raw Arena.used() byte counts, which the Node shim reports as 0
cases/mem_arena_builtins   # prints arena byte usage
cases/mem_scope_dynamic_array  # prints the arena delta across scoped calls

# Calls C, so there is no Node program to compare against (WP27 S1). This is not
# a discrepancy to be closed: `abs` is a libc symbol, the shim has no counterpart
# for it, and giving it one would only move the question to the next foreign
# symbol a program declares. Every `declare function` program is outside this
# oracle by construction, which is a real coverage cost of the feature and is why
# `tests/cases/ffi_scalar` carries a golden `.ll` and a native round trip instead.
cases/ffi_scalar           # declare function abs/labs: libc, with no JS equivalent
cases/ffi_pointer          # declare function calloc/realloc/free: the same, with a CPtr (WP27 S2)
cases/ffi_string_param     # declare function strlen/atoi/setenv/puts: libc string calls (WP27 S3.1)
cases/ffi_string_return    # declare function strerror/getenv/setlocale/strchr: libc string results (WP27 S3.2)
cases/ffi_string_loops     # declare function strerror/getenv in loops: libc string results (WP27 S3.2)
cases/ffi_owned_string     # declare function strdup/realpath/free with readCString: libc-owned buffers copied (WP27 S3.3)
cases/ffi_buffer_call_sites   # declare function write with u8[] buffers from every kind of call site (WP40 B1.2)
cases/ffi_buffer_count_proved # declare function write: counts the checker proves and counts it checks (WP40 B1.2)
cases/ffi_buffer_late_load    # declare function write: the length read after every argument (WP40 B1.2)
cases/ffi_buffer_memcpy       # declare function memcpy: two buffers, one count (WP40 B1.2)
cases/ffi_buffer_write        # declare function write: libc, with no JS equivalent (WP40 B1.2)
