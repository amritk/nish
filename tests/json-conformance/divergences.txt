# The test262 and V8 cases (test262.txt, v8.txt) that nish/json-tokenizer and
# JsonWriter answer differently from JSON.parse and JSON.stringify, on purpose.
# tests/link/std_json_conformance holds every case named here to the answer its
# reason gives, and every case not named here to upstream's value.
#
# A reason is `reason <key> <answer> <sentence>`. `answer` is what a case listed
# under it answers instead: `unindented`, upstream's text with the indentation
# its space put in taken out; `text`, a whole text other than upstream's; or a
# comma-separated list of the tokenizer's error names, one of which the case
# must stop at. Then one line per case: `<name> <key>`.
#
# `build/test/link/std_json_conformance/app --mismatches`, run from the
# repository root, prints every case whose answer is not upstream's.

reason lone-surrogate SURROGATE A string holding a lone surrogate. JSON.stringify escapes one as \udxxx, but a Nish string is UTF-8, which cannot hold one, so the case's value has no Nish spelling: the escape that spells it is refused by the tokenizer (docs/security/json.md, "Lone surrogates").
reason indent unindented JSON.stringify with a space: JsonWriter writes no indentation yet, so the case answers upstream's text without it. The writer-modes stage of json-parity adds indentation.
reason depth DEPTH A nesting past JsonLimits.maxDepth, 128 by default: V8 parses 10,001 levels, and the tokenizer refuses the 129th opener, its defence against a depth bomb (docs/security/json.md, "Depth bombs").
reason duplicate-key text A key repeated in one object. JSON.parse keeps the last value at the first one's place; the tokenizer hands on both members, because which one wins is the reader's decision (docs/security/json.md, JSON-3), so the rewrite writes both.
