# The parser-refusal register: the cases stage1 turns down in its *parser*,
# before the phase that owns the rule can state it.
#
# One entry per line, two fields:
#
#   <case>   <the syntax error stage1 answers with>
#
# <case> is a name under `tests/cases`, without the extension, or `link/<name>`
# for a whole program under `tests/link`. The sentence is stage1's first line
# of output, less its `file:line:column:` span and less the `syntax error: `
# that every line here would otherwise carry — that prefix is what names the
# bucket rather than part of what stage1 says. Blank lines and lines
# whose first non-blank character is `#` are ignored; a `#` inside a sentence
# is part of it.
#
# What an entry *means*, in the tool that reads this file:
#
#   - `tests/self/reject-oracle.js` counts the case in its parser bucket
#     instead of holding stage1's message against the fragments the case's
#     `.err` pins. The two wordings are different on purpose — lex and parse
#     what is written, refuse in the phase that owns the rule
#     (`.claude/selfhost.md`), and a sentence about the operator the programmer
#     wrote beats one about a node kind — so the bucket is a measurement rather
#     than a hole, and this file is that measurement written down.
#
# The oracle compares the register against the bucket in both directions on
# every unfiltered run, which is the whole of why the file exists:
#
#   - a case in the bucket and not here fails. That is a rule leaving the
#     checker's reach, and it is the migration `docs/wp19-stage0-retirement.md`
#     §5's R3 row said nothing was watching for: "the reject oracle's parser
#     bucket is a count in a summary line and nothing compares it to a ceiling,
#     so the next rule that leaves the parser's reach migrates a case into the
#     bucket silently."
#   - a case here and not in the bucket fails too, and that direction matters
#     as much: the register's purpose is to *shrink*. The member-header family
#     — `x?: T`, `x!: T`, `m?()` and `static` — left the parser for the checker
#     in 0.3.0 and took the bucket from 92 to 89. A register that only ever
#     grew would have recorded that improvement as an unchanged number.
#   - the sentence is compared as well, so an entry is a claim about what
#     stage1 prints today rather than a note somebody wrote once. A reworded
#     parser message fails the run and the failure quotes the new sentence.
#
# What an entry does *not* pin is stage1's output past its first line. A case
# that starts printing four syntax errors where it printed one keeps its entry
# and its sentence, and nothing here notices — which is the shape a class
# member *named* `static` had until 0.3.0. This is a ceiling on what is in the
# bucket, not a golden for what the bucket prints.
#
# The central form is deliberate. Every other per-case expectation in this
# suite is a sidecar beside the program — `.err`, `.args`, `.ll`, `.out` — and
# a `tests/cases/<case>.stage1.err` would put these sentences under the same
# convention and leave this file a list of names. It would also scatter the one
# thing the file exists to show: the set, in one place, countable in one look.
#
# `tests/wordings/parser_refusals.txt` is this file's sister and not a
# duplicate of it: the same §A3 class, measured over `tests/wordings/` — one
# program per diagnostic code — where an entry means the *code*'s wording is
# stage0's alone. This one is measured over the `reject_*` goldens and the
# `tests/link/` negatives, where an entry means the *case*'s fragments are.
#
# Two rules the file cannot enforce and a reviewer must:
#
#   1. An entry is a measurement, never a licence. These sentences are what
#      the user sees after R6, when stage0's are gone, and a sentence that
#      cannot name the member, the rule or the class it belongs to is worth
#      moving to the phase that can — which is how the member-header family
#      came off. Registering a case records the state; it does not settle it.
#   2. This file records what stage1's parser does, and never decides it.
#      Moving a case in or out is a rule changing phase, which is a language
#      change: it belongs to the change that moves the rule, with the case's
#      `.err`, §A3's declaration and this entry all updated together, not to a
#      line edited until the run goes green.
