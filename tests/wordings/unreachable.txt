# Registry codes no program can provoke, one `CODE  reason` per line.
#
# `tests/diagnostic_coverage.js` requires every code in `self/codes.ts` to be
# either provoked by the corpus or named here, so a diagnostic cannot quietly
# arrive without a test. A code listed here that turns out to be reachable is a
# failure as well: the list may shrink, and it may not rot.
#
# An unreachable diagnostic is a finding about the compiler rather than a test
# nobody wrote, which is why each line says which kind it is. None of them is a
# bug in what the compiler *does*; between them they say that `RULE_COUNT` is
# about fifteen percent larger than the number of rules a user can actually be
# shown.

# --- Backstops: reachable, but only by a program this corpus will not carry. --
# WP18's two instantiation caps. They are not rules of the language and their
# messages say so; they exist to stop a program that asks for an absurd number
# of specialisations without tripping the termination rule. Provoking one needs
# 257 distinct type-argument tuples for a single template, or 4,097 in a module,
# and a program that size is a stress test rather than a wording case: it would
# be the largest file in `tests/` and would spend the suite's time proving a
# constant. The wordings are held by the `MAX_INSTANTIATIONS*` constants they
# interpolate, which `docs/wp18-generics.md` §4 documents.
#
# This is the one kind of entry here that is a judgement about the corpus rather
# than a fact about the compiler, and it is the kind to look at first if this
# list ever starts growing.
