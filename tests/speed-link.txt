# The tests/link programs that link under `--profile speed` (-O3 with LTO) in
# both harnesses, tests/run.js (`linkProfile`) and tests/nish/run.ts
# (`linkProfileArgs`). Every other program links under `--profile debug` (no
# optimiser, no LTO, the runtime's asserts on) unless its `args` name a profile
# of its own. The profile changes the link, never a byte of the IR
# (src/compile.ts), so the goldens, expected.ir and the wipe checks read what
# they always read.
#
# Measured on main at 804120e, every positive program built under each profile
# on one 4-core machine, speed twice:
#   541 positive programs   build    run   total
#   speed, first          738.5 s  83.6 s  822.1 s
#   speed, second         735.1 s  64.0 s  799.1 s
#   debug                 173.1 s 171.7 s  344.8 s
# The two speed passes differ by 0.5% in build and 23 s in run (the first run
# of each binary pays a cold start), so the band is about 3%; debug saves
# 454-477 s, far outside it, and the default is debug. No program's exit code
# or stdout differed between the profiles; only stderr's timings and addresses
# did.
#
# One program per line: its directory name, then the reason it keeps the speed
# profile. A `#` line is a comment. tests/run.js checks that every name is a
# program and that no program here names a profile in its args.
