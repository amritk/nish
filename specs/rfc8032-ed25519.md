--- abstract

A profile of RFC 8032 for nish/crypto/ed25519: PureEdDSA Ed25519 key
generation, signing and verification. Every requirement quotes RFC 8032, the
main source; every binding sentence of RFC 8032 (MUST, MUST NOT, SHALL, SHALL
NOT, REQUIRED) is tested or excluded here.

--- middle

# Introduction

{::boilerplate bcp14-tagged}

nish/crypto/ed25519 implements Ed25519 as RFC 8032 Section 5.1 defines it,
with an empty context and no prehash. The private key is the 32-octet seed,
which the module takes as a `Secret`. Key generation and signing return
`u8[] | null`, null for a seed of the wrong length; verification returns a
boolean.

# Interface

~~~ ts-interface
// module: nish/crypto/ed25519
export const ed25519PublicKey = (seed: Secret<u8[]>): u8[] | null
export const ed25519Sign = (seed: Secret<u8[]>, msg: u8[]): u8[] | null
export const ed25519Verify = (pub: u8[], msg: u8[], sig: u8[]): boolean
~~~

# Ed25519

> For Ed25519, dom2(f,c) is the empty string.
> {{Section 5.1 of RFC8032}}
{: #R-PURE gi="blockquote"}

> The context (if present at all) MUST be empty.
> {{Section 5.1 of RFC8032}}
{: gi="blockquote"}

Untested: nish implements PureEdDSA Ed25519 only: no function takes a context, so it is always empty

# Key Generation

> The 32-byte public key is generated by the following steps.
> {{Section 5.1.5 of RFC8032}}
{: #R-PUB-32 gi="blockquote"}

> The public key A is the encoding of the point [s]B.
> {{Section 5.1.5 of RFC8032}}
{: #R-PUB-ENCODE gi="blockquote"}

# Sign

> Form the signature of the concatenation of R (32 octets) and the little-endian encoding of S (32 octets; the three most significant bits of the final octet are always zero).
> {{Section 5.1.6 of RFC8032}}
{: #R-SIG-FORM gi="blockquote"}

# Verify

> If any of the decodings fail (including S being out of range), the signature is invalid.
> {{Section 5.1.7 of RFC8032}}
{: #R-VERIFY-DECODE gi="blockquote"}

> Check the group equation [8][S]B = [8]R + [8][k]A'.
> {{Section 5.1.7 of RFC8032}}
{: #R-VERIFY-EQ gi="blockquote"}

# Security Considerations

> In particular, unless the underlying protocol does not require it, the receiver MUST buffer the entire message (or enough information to reconstruct it, e.g., compressed or encrypted version) to be verified.
> {{Section 8.7 of RFC8032}}
{: gi="blockquote"}

Untested: an obligation on the caller: ed25519Verify takes the whole message, and what the receiver does with it is outside the module

# Out of Scope

Ed25519ctx and Ed25519ph (RFC 8032 Section 5.1) and Ed448 and Ed448ph
(Section 5.2) are not exported, so their sections and their test vectors
(Sections 7.2 to 7.5) are not part of this profile.

Three statements of RFC 8032 are not functional and hold no BCP 14 keyword,
so they are recorded here, not excluded:

- Section 5.1.5: the private key is "cryptographically secure random data".
  The seed is the caller's input, and its randomness is not observable by a
  test.
- Section 8.1: "the modulo p arithmetic must not use any data-dependent
  branches". Timing is not observable by a functional test. nish checks the
  field arithmetic Ed25519 shares with X25519 on the emitted machine code
  (tests/cases/ct\_asm\_x25519.ts) and records the rest in
  docs/security/crypto-ecc.md (ECC-5).
- Section 8.1: "secrecy of the private key is fundamental". nish takes the
  seed as a `Secret` and pins the wipes of its hash, the nonce and the
  scratch under opt -O2 (tests/wipes/crypto.js, tests/run.js), recorded in
  docs/security/crypto-ecc.md.

Of Section 7.1, only the public keys are vectors:

- Signatures: a signing row must name its message by the label the section
  prints, such as "MESSAGE (length 1 byte)", and a `Call` label admits only
  letters, digits, `-` and spaces. TEST 1's empty message is also printed
  only as a length. TEST 1024's 1023-byte message fits as hex pairs; only
  its label blocks it.
- Verification: a row expecting `true` must cover a requirement cited to
  Section 7.1 that states the result, and the section states none.

The properties hold signing and verification instead, and
tests/link/crypto\_ed25519/rfc.ts signs and verifies all five Section 7.1
tests against the printed signatures.

std/crypto/ed25519.ts also exports three `i32` constants, which a vector or
property cannot call:

- ED25519\_SEED\_SIZE: the 32-octet seed every property draws.
- ED25519\_PUBLIC\_KEY\_SIZE: held by P-PUB-32.
- ED25519\_SIGNATURE\_SIZE: held by P-SIG-FORM.

vector 0.2.1 cannot declare `outOfScope` exports, so this section is their
record.

# Properties

~~~ ts-property
// P-PUB-32 covers R-PUB-32 — any 32-octet seed gives a 32-byte public key
forall (seed: u8[] /* 32..32 */) =>
  unwrap(ed25519PublicKey(seed)).length === 32
~~~

~~~ ts-property
// P-SIG-FORM covers R-SIG-FORM — a signature is 64 octets and the three most significant bits of its final octet are zero
forall (seed: u8[] /* 32..32 */, msg: u8[] /* 0..130 */) =>
  { const sig = unwrap(ed25519Sign(seed, msg)); return sig.length === 64 && bitAnd(sig.slice(63, 64), fill(224, 1)) === zeros(1); }
~~~

~~~ ts-property
// P-ROUNDTRIP covers R-VERIFY-EQ, R-PURE — a signature verifies under the seed's public key
forall (seed: u8[] /* 32..32 */, msg: u8[] /* 0..130 */) =>
  ed25519Verify(unwrap(ed25519PublicKey(seed)), msg, unwrap(ed25519Sign(seed, msg))) === true
~~~

~~~ ts-property
// P-TAMPER-SIG covers R-VERIFY-EQ — flipping any one bit of the signature makes it invalid
forall (seed: u8[] /* 32..32 */, msg: u8[] /* 0..100 */, bit: i32 /* 0..511 */) =>
  ed25519Verify(unwrap(ed25519PublicKey(seed)), msg, flipBit(unwrap(ed25519Sign(seed, msg)), bit)) === false
~~~

~~~ ts-property
// P-TAMPER-MSG covers R-VERIFY-EQ — flipping any one bit of the message makes the signature invalid
forall (seed: u8[] /* 32..32 */, msg: u8[] /* 1..100 */, bit: i32 /* 0..799 */) =>
  ed25519Verify(unwrap(ed25519PublicKey(seed)), flipBit(msg, bit), unwrap(ed25519Sign(seed, msg))) === false
where bit < 8 * msg.length
~~~

~~~ ts-property
// P-S-RANGE covers R-VERIFY-DECODE — setting any of the three top bits of S puts it out of range, and the signature is invalid
forall (seed: u8[] /* 32..32 */, msg: u8[] /* 0..100 */, bit: i32 /* 509..511 */) =>
  ed25519Verify(unwrap(ed25519PublicKey(seed)), msg, flipBit(unwrap(ed25519Sign(seed, msg)), bit)) === false
~~~

~~~ ts-property
// P-SIZES covers R-VERIFY-DECODE — a public key other than 32 octets or a signature other than 64 is invalid
forall (seed: u8[] /* 32..32 */, msg: u8[] /* 0..40 */, cut: i32 /* 1..32 */) =>
  { const pub = unwrap(ed25519PublicKey(seed)); const sig = unwrap(ed25519Sign(seed, msg)); return ed25519Verify(pub.slice(0, 32 - cut), msg, sig) === false && ed25519Verify(pub, msg, sig.slice(0, 64 - cut)) === false; }
~~~
