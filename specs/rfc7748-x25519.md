--- abstract

A profile of RFC 7748 for nish/crypto/x25519: the X25519 function, its
scalar and u-coordinate encodings, the iterated test vectors and the
Diffie-Hellman exchange on Curve25519. Every requirement quotes RFC 7748, the
main source; every binding sentence of RFC 7748 (MUST, MUST NOT, SHALL, SHALL
NOT, REQUIRED) is tested or excluded here. X448 is not implemented and not
profiled.

--- middle

# Introduction

{::boilerplate bcp14-tagged}

nish/crypto/x25519 exports `x25519`, the function of RFC 7748 Section 5, and
`x25519Base`, the same function on the base point u = 9. The scalar and the
shared secret are `Secret` values; the properties see them as bytes. Both
functions return null unless every argument is 32 bytes, and an all-zero
result (Section 6.1) is returned, not refused, so no clause here tests a
refusal of it.

The field helpers the module also exports (`f25519Add64`, `f25519Sub64`,
`f25519Mul64`, `f25519Zero`, `f25519Small`, `f25519Copy`, `f25519Carry`,
`f25519Add`, `f25519Sub`, `f25519Mul`, `f25519Square`, `f25519SquareTimes`,
`f25519Pow250`, `f25519Invert`, `f25519Swap`, `f25519Decode`,
`f25519Encode`) and `X25519_SIZE` are internal to the ladder and outside this
profile: RFC 7748 specifies the function, not its field arithmetic.

The iterated vectors of Section 5.2 are tested for one iteration only. The
1,000,000-iteration vector is excluded for its run time: a million calls of
the ladder on every run. The 1,000-iteration vector is excluded because
vector 0.2.1 cannot express it: the RFC prints no intermediate value to chain
vectors through, and a property that names each step as a `const` grows
exponentially, since each step uses the previous two and consts are expanded
inline.

The Section 6.1 test vector is the property P-DH-VECTOR rather than vector
rows: the section prints its values under names such as "Alice's private
key, a", which a vector label cannot spell, and the profile refuses an
unlabelled value printed under a name. Its bytes are transcribed from the
RFC, so fidelity does not check them. Its `zero` argument takes the single
value 0: a property needs a `forall` argument, and this one has no input to
vary.

# The X25519 Function

> The functions take a scalar and a u-coordinate as inputs and produce a u-coordinate as output.
> {{Section 5 of RFC7748}}
{: #R-FUNC gi="blockquote"}

> Although the functions work internally with integers, the inputs and outputs are 32-byte strings (for X25519) or 56-byte strings (for X448) and this specification defines their encoding.
> {{Section 5 of RFC7748}}
{: #R-SIZE gi="blockquote"}

> When receiving such an array, implementations of X25519 (but not X448) MUST mask the most significant bit in the final byte.
> {{Section 5 of RFC7748}}
{: #R-MASK gi="blockquote"}

> Implementations MUST accept non-canonical values and process them as if they had been reduced modulo the field prime.
> {{Section 5 of RFC7748}}
{: #R-NONCANON gi="blockquote"}

> For X25519, in order to decode 32 random bytes as an integer scalar, set the three least significant bits of the first byte and the most significant bit of the last to zero, set the second most significant bit of the last byte to 1 and, finally, decode as little-endian.
> {{Section 5 of RFC7748}}
{: #R-CLAMP gi="blockquote"}

> Finally, encode the resulting value as 32 or 56 bytes in little- endian order.
> {{Section 5 of RFC7748}}
{: #R-ENCODE gi="blockquote"}

> For X25519, the unused, most significant bit MUST be zero.
> {{Section 5 of RFC7748}}
{: #R-OUT-MSB gi="blockquote"}

> The cswap function SHOULD be implemented in constant time (i.e., independent of the swap argument).
> {{Section 5 of RFC7748}}
{: gi="blockquote"}

Untested: timing is not observable by a functional test; nish checks it on the emitted machine code (tests/cases/ct\_asm\_x25519.ts, tests/ct-timing.js, docs/security/ct-verification.md, docs/security/crypto-ecc.md)

# Diffie-Hellman

> Alice generates 32 random bytes in a[0] to a[31] and transmits K\_A = X25519(a, 9) to Bob, where 9 is the u-coordinate of the base point and is encoded as a byte with value 9, followed by 31 zero bytes.
> {{Section 6.1 of RFC7748}}
{: #R-BASE gi="blockquote"}

> Both now share K = X25519(a, X25519(b, 9)) = X25519(b, X25519(a, 9)) as a shared secret.
> {{Section 6.1 of RFC7748}}
{: #R-DH gi="blockquote"}

# Deterministic Generation

> The trace of Frobenius MUST NOT be in {0, 1} in order to rule out the attacks described in [smart], [satoh], and [semaev], as in [brainpool] and [safecurves].
> {{Appendix A of RFC7748}}
{: gi="blockquote"}

Untested: an obligation on choosing a curve, which Curve25519 already meets; nothing an implementation of X25519 does can satisfy or violate it

> MOV Degree [reducing]: the embedding degree MUST be greater than (order - 1) / 100, as in [brainpool] and [safecurves].

# Properties

~~~ ts-property
// P-SIZES covers R-FUNC, R-SIZE — X25519 answers exactly when the scalar and the u-coordinate are both 32 bytes
forall (k: u8[] /* 0..40 */, u: u8[] /* 0..40 */) =>
  (k.length === 32 && u.length === 32) === (x25519(k, u) !== null)
~~~

~~~ ts-property
// P-OUT-32 covers R-SIZE, R-ENCODE — the output u-coordinate is 32 bytes
forall (k: u8[] /* 32..32 */, u: u8[] /* 32..32 */) =>
  unwrap(x25519(k, u)).length === 32
~~~

~~~ ts-property
// P-MASK covers R-MASK — the most significant bit of the final byte of u does not change the result
forall (k: u8[] /* 32..32 */, u: u8[] /* 32..32 */) =>
  x25519(k, u) === x25519(k, flipBit(u, 255))
~~~

~~~ ts-property
// P-NONCANON covers R-NONCANON — u = p + d for the 19 non-canonical values gives the result for u = d
forall (k: u8[] /* 32..32 */, d: i32 /* 0..18 */) => {
  const p = fill(237 + d, 1).concat(fill(255, 30)).concat([7f]);
  return x25519(k, p) === x25519(k, fill(d, 1).concat(zeros(31)));
}
~~~

~~~ ts-property
// P-NONCANON-MASKED covers R-NONCANON, R-MASK — a non-canonical u with the top bit set is masked, then reduced
forall (k: u8[] /* 32..32 */, d: i32 /* 0..18 */) => {
  const p = fill(237 + d, 1).concat(fill(255, 31));
  return x25519(k, p) === x25519(k, fill(d, 1).concat(zeros(31)));
}
~~~

~~~ ts-property
// P-CLAMP covers R-CLAMP — the three low bits of the first byte and the top two bits of the last do not change the result
forall (k: u8[] /* 32..32 */, u: u8[] /* 32..32 */) => {
  const keep = [f8].concat(fill(255, 30)).concat([3f]);
  const set = zeros(31).concat([40]);
  return x25519(k, u) === x25519(bitOr(bitAnd(k, keep), set), u);
}
~~~

~~~ ts-property
// P-OUT-MSB covers R-OUT-MSB — the most significant bit of the output is zero
forall (k: u8[] /* 32..32 */, u: u8[] /* 32..32 */) =>
  bitAnd(unwrap(x25519(k, u)).slice(31, 32), [80]) === [00]
~~~

~~~ ts-property
// P-BASE covers R-BASE — x25519Base(a) is X25519(a, 9), with 9 a byte of value 9 followed by 31 zero bytes
forall (k: u8[] /* 32..32 */) =>
  x25519Base(k) === x25519(k, [09].concat(zeros(31)))
~~~

~~~ ts-property
// P-DH covers R-DH — X25519(a, X25519(b, 9)) equals X25519(b, X25519(a, 9))
forall (a: u8[] /* 32..32 */, b: u8[] /* 32..32 */) =>
  x25519(a, unwrap(x25519Base(b))) === x25519(b, unwrap(x25519Base(a)))
~~~

~~~ ts-property
// P-DH-VECTOR covers R-BASE, R-DH — the Section 6.1 test vector: Alice's and Bob's public keys and their shared secret K
forall (zero: i32 /* 0..0 */) => {
  const a = [77 07 6d 0a 73 18 a5 7d 3c 16 c1 72 51 b2 66 45 df 4c 2f 87 eb c0 99 2a b1 77 fb a5 1d b9 2c 2a];
  const ka = [85 20 f0 09 89 30 a7 54 74 8b 7d dc b4 3e f7 5a 0d bf 3a 0d 26 38 1a f4 eb a4 a9 8e aa 9b 4e 6a];
  const b = [5d ab 08 7e 62 4a 8a 4b 79 e1 7f 8b 83 80 0e e6 6f 3b b1 29 26 18 b6 fd 1c 2f 8b 27 ff 88 e0 eb];
  const kb = [de 9e db 7d 7b 7d c1 b4 d3 5b 61 c2 ec e4 35 37 3f 83 43 c8 5b 78 67 4d ad fc 7e 14 6f 88 2b 4f];
  const k = [4a 5d 9d 5b a4 ce 2d e1 72 8e 3b f4 80 35 0f 25 e0 7e 21 c9 47 d1 9e 33 76 f0 9b 3c 1e 16 17 42];
  return zero === 0 && x25519Base(a) === ka && x25519Base(b) === kb && x25519(a, kb) === k && x25519(b, ka) === k;
}
~~~
