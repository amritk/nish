# Message classes from a `.proto` file: `nish proto`

A service that speaks protobuf reads each message with
[`nish/net/protobuf`](standard-library.md#nishnetprotobuf): a loop over the
fields, a test of each field number, a typed read. `nish proto` writes those
loops for you. It reads a proto3 file and writes one Nish module with a class
per message, each with an `encode` onto a `ProtoWriter` and a `decode` from a
`ProtoReader`. You check the module in and import it like any other
([`export` and `import`](../../reference/language/declarations.md#export-and-import));
the `.proto` file is only read again when you regenerate.

```console
$ nish proto calc.proto -o calc.ts
$ nish proto calc.proto -o calc.ts --check
```

The second line writes nothing: it exits 1 and prints
`proto: calc.ts is stale; regenerate it` when the module it would write is not
the one on disk, byte for byte. Run it in CI next to your other checks.

## A first module

This file declares the two messages of a sum service:

```proto calc.proto
syntax = "proto3";

package calc;

message SumRequest {
  int32 a = 1;
  int32 b = 2;
}

message SumReply {
  int32 result = 1;
}
```

`nish proto calc.proto -o calc.ts` writes this module. The header names the
file and the SHA-256 of its bytes, and the command that regenerates it:

<!-- nish:ok -->
```ts calc.ts
// Generated by nish proto from calc.proto (sha256 b6cba32f506170281cd4187633a9b71e8da22d95c8a466e60cb1fb81376eb27e). Do not edit; regenerate it.
// Regenerate: nish proto calc.proto -o calc.ts

import { PROTO_OK, PROTO_WIRE_VARINT, ProtoReader, ProtoWriter } from "nish/net/protobuf"

export class SumRequest {
  a: i32 = 0
  b: i32 = 0

  /** Writes this message's fields onto `w`, in field-number order. */
  encode(w: ProtoWriter): void {
    if (this.a !== 0) {
      w.int32(1, this.a)
    }
    if (this.b !== 0) {
      w.int32(2, this.b)
    }
  }

  /** Reads fields from the reader's current span until its end, merging them into this message; false on a fault. */
  decode(r: ProtoReader): boolean {
    while (r.next()) {
      if (r.field === 1 && r.wireType === PROTO_WIRE_VARINT) {
        this.a = r.int32()
      } else if (r.field === 2 && r.wireType === PROTO_WIRE_VARINT) {
        this.b = r.int32()
      }
    }
    return r.failed === PROTO_OK
  }
}

export class SumReply {
  result: i32 = 0

  /** Writes this message's fields onto `w`, in field-number order. */
  encode(w: ProtoWriter): void {
    if (this.result !== 0) {
      w.int32(1, this.result)
    }
  }

  /** Reads fields from the reader's current span until its end, merging them into this message; false on a fault. */
  decode(r: ProtoReader): boolean {
    while (r.next()) {
      if (r.field === 1 && r.wireType === PROTO_WIRE_VARINT) {
        this.result = r.int32()
      }
    }
    return r.failed === PROTO_OK
  }
}
```

A program encodes a request into a writer and decodes it from a reader over
the writer's bytes, as a server reading a request body would. `decode` answers
false on malformed bytes; the fault is left in the reader's `failed`. The
sum is computed only for operands it has tested, so it builds under the
default panic rule:

<!-- nish:ok -->
```ts main.ts
import { SumReply, SumRequest } from "./calc"
import { ProtoReader, ProtoWriter } from "nish/net/protobuf"

// The reply to a request, or null when its bytes are malformed or an operand
// is outside 0 to 1000000.
const answer = (bytes: u8[], length: i32): SumReply | null => {
  const req = new SumRequest()
  if (!req.decode(new ProtoReader(bytes, 0, length))) {
    return null
  }
  const a = req.a
  const b = req.b
  if (a < 0 || a > 1000000 || b < 0 || b > 1000000) {
    return null
  }
  const reply = new SumReply()
  reply.result = a + b
  return reply
}

export const main = (): i32 => {
  const req = new SumRequest()
  req.a = 2
  req.b = 40
  const w = new ProtoWriter([])
  req.encode(w)

  const reply = answer(w.buf, w.end)
  if (reply !== null) {
    console.log(`2 + 40 = ${reply.result}`)
  }
  return 0
}
```

It prints `2 + 40 = 42`. With [`nish/net/grpc`](grpc.md), the same `decode`
reads a call's request and `encode` writes its reply.

## What it writes

| proto3 | Nish |
| --- | --- |
| `int32`, `sint32`, `sfixed32` | `i32` |
| `uint32`, `fixed32` | `u32` |
| `int64`, `sint64`, `sfixed64` | `i64` |
| `uint64`, `fixed64` | `u64` |
| `float`, `double` | `f32`, `f64` |
| `bool`, `string`, `bytes` | `boolean`, `string`, `u8[]` |
| an enum | `i32`, and an `i32` constant per value |
| a message | `C \| null`, `null` until it is set or read |
| `repeated T` | `T[]` |
| `optional T` | the field, and for a scalar a `has_<field>: boolean`; a message is present when it is not `null` |
| `map<K, V>` | `Map<K, V>`; `K` is an integer type, `bool` or `string` |
| a `oneof` | each member a field, and `<oneof>_case: i32` |
| a service | a `string` constant per method, holding its path |

- **Names.** A class keeps its message's name. A nested message or enum is
  named after its parents, `Outer_Inner`. A field keeps its name from the
  file, so `has_count` and `size_case` read the way the `.proto` file is
  written. The classes are in the file's order and their fields in field
  order, which can leave padding between fields: the compiler may warn about
  it, and the warning is only about speed.
- **Enums** are open in proto3: a reader keeps a value no member names. So an
  enum field is an `i32`, and each value is a constant named
  `<Enum>_<VALUE>`: `Color_COLOR_RED` for `COLOR_RED = 1` in `enum Color`.
- **Defaults** are proto3's: 0, `false`, `""`, an empty array or map, and
  `null` for a message. `encode` does not write a field equal to its default,
  as proto3 requires; an `optional` field is written whenever its `has_` flag
  is set, and a message field whenever it is not `null`.
- **A oneof** holds at most one member: `<oneof>_case` is the field number of
  the member that is set, or 0. Set the member and the case together. `decode`
  clears the other members when it reads one.
- **A service method** is a constant named `<SERVICE>_<METHOD>` in upper
  snake case, holding the path a gRPC client posts to:
  `CALC_SUM: string = "/calc.Calc/Sum"` for `rpc Sum` in `service Calc` of
  `package calc`. It is the path you add to your router.

`decode` merges into the object it is called on, as the protobuf reference
implementation does: the last value of a singular field wins, a message field
read twice is merged, a `repeated` field appends, and a map entry replaces the
one with the same key. A field the class does not declare is skipped, and so
is a field sent with a wire type its declaration does not have. Repeated
numbers are written packed and read either way.

## Bounds on what a reader is sent

A decoder reads bytes another process chose, so the module keeps the reader's
limits:

- A nested message is read between `r.enter()` and `r.leave()`, so a message
  nested deeper than the reader's limit (100 levels) is refused with
  `r.failed` set, and `decode` answers false.
- A `repeated` field or a map grows by one element or entry per field read,
  and every read consumes at least one byte, so neither grows past the
  message's length.
- A `string` or `bytes` field is copied out of the reader's span and never
  past it.

## What is refused

Everything outside the subset above is refused with the construct's name and
its line, and nothing is written, so a failed regeneration leaves the
checked-in module as it was:

```console
$ nish proto calc.proto -o calc.ts
proto: calc.proto:1: refused: proto2 syntax (only proto3 is supported)
```

- `syntax = "proto2"`, `edition`, and a file with no `syntax` line;
- `import`: one file is one module;
- `required`, `group`, `extend` and `extensions`, which are proto2's;
- `stream` methods, and methods whose request or reply is an enum or a type
  the file does not declare, including `google.protobuf.*`;
- a field option (`[packed = false]`, `[deprecated = true]`), a message, enum,
  oneof, service or method option, and any file option but the language
  options other generators read (`java_*`, `go_*`, `php_*`,
  `csharp_namespace`, `objc_class_prefix`, `ruby_package`, `swift_prefix`,
  `optimize_for`), which are ignored and listed in the header;
- a field number outside 1 to 536870911, in the 19000 to 19999 range the
  encoding keeps for itself, used twice, or reserved; a field name reserved;
- a map key of `float`, `double`, `bytes`, an enum or a message, a map of a
  map, and a `repeated`, `map` or `optional` field inside a `oneof`;
- an enum with no values, a first value that is not 0, two values with one
  number, a value outside `int32`, or an enum option; `reserved` in an enum is
  refused too, even where protoc accepts it, so write its numbers and names in
  a comment instead;
- a second `package` statement, a package name that starts with a dot, and
  messages nested more than 32 deep;
- an empty `oneof`, and a `reserved` range that is backwards or starts
  below 1;
- two declarations with one name in one scope, and a name that would clash in
  the module: a keyword, `encode` or `decode`, a `has_` or `_case` name
  another field already takes, two constants with one name, or an enum value
  or service method whose constant would start with `PROTO_`, the prefix of
  the names the module imports from `nish/net/protobuf`.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | the module was written, or `--check` found it current |
| 1 | refused, or `--check` found the module missing or different |
| 2 | usage: no `.proto` file, no `-o`, an unknown flag, an input that cannot be read, `-o` naming the input, or a path holding a quote, a backslash, a comment delimiter or a byte that is not printable ASCII |
