# Binding a C library: `nish c-import`

Calling a C library means writing a `declare function` for each function you
call, a `declare class` for each struct it reads, and a constant for each
`#define` and enum you pass. `nish c-import` writes that module for you from
the library's header, and lists what it could not bind. You check the module
in and import it like any other; the header is only read again when you
regenerate.

```console
$ nish c-import wc.h -o wc.ts
```

The declarations it writes are the ones
[Calling Nish from other languages](interop.md#calling-c-from-nish-declare-function)
describes, under the rules of
[LANGUAGE.md → Calling C](https://github.com/amritk/nish/blob/main/docs/LANGUAGE.md#calling-c).
The command needs `clang`: it is clang that reads the header, with the same
preprocessor and the same answers about sizes your C compiler gives. Set `CC`
to use another clang.

## What it writes

Given this header:

```c
#include <stddef.h>
#include <stdint.h>

#define WC_MAX_WORD 64
#define WC_NAME "wc"
enum wc_mode { WC_BYTES, WC_WORDS = 2 };

typedef struct counter counter;
struct wc_span { int64_t start; int64_t len; };

counter *wc_new(enum wc_mode mode);
int wc_feed(counter *c, const char *text);
int64_t wc_total(counter *c, int64_t *words);
int wc_last(counter *c, struct wc_span *span);
char *wc_report(counter *c);
void wc_free(counter *c);
void wc_free_report(char *r);
int wc_log(const char *format, ...);
```

`nish c-import wc.h -o wc.ts` writes:

```ts wc.ts
// Generated by nish c-import from wc.h. Do not edit; regenerate it.
// Target: x86_64-unknown-linux-gnu
// Data model: LP64
// Regenerate: nish c-import wc.h --target x86_64-unknown-linux-gnu -o wc.ts

declare class OutI64 {
  value: i64
}

declare class wc_span {
  start: i64
  len: i64
}

export const WC_BYTES: i32 = 0
export const WC_WORDS: i32 = 2
export const WC_MAX_WORD: i32 = 64
export const WC_NAME: string = "wc"

declare function wc_new(mode: i32): CPtr | null
declare function wc_feed(c: CPtr, text: string): i32
declare function wc_total(c: CPtr, words: OutI64): i64
declare function wc_last(c: CPtr, span: wc_span): i32
declare function wc_report(c: CPtr): CPtr | null
declare function wc_free(c: CPtr): void
declare function wc_free_report(r: CPtr): void

/* Not bound:
 *   wc_log: variadic
 */
```

Each part of the header becomes one kind of declaration:

| In the header | In the module |
| --- | --- |
| a function | a `declare function` with the same name |
| a struct of numbers and pointers | a `declare class` with the same fields; a pointer field is `CPtr \| null` |
| a struct the header only names (`typedef struct counter counter`) | nothing: a pointer to it is a `CPtr` |
| an enum constant, an integer `#define` | an `export const` of `i32`, `i64` or `u64` |
| a string `#define` | an `export const` of `string` |
| a pointer to a number a function writes into (`int64_t *`) | an out class, `OutI64`, with one `value` field |

The C integer types become the Nish width of the same size and sign on the
target: `int` is `i32`, `int64_t` and `long long` are `i64`, `size_t` is `u64`
on a 64-bit target and `u32` on wasm32. `float` and `double` are `f32` and
`f64`, `_Bool` is `boolean`.

The defaults for pointers are the safe ones:

- A `const char *` parameter is a `string`; a `const char *` result is
  `string | null`.
- A pointer to a struct the header only names is a `CPtr`; a result is
  `CPtr | null`, since C may hand back `NULL`.
- Any other `char *` result is a `CPtr | null`: the module cannot know
  whether you must free it.

A module that uses an out class declares it, so two modules can each declare
`OutI64`: they are the same class.

## Using the module

Import what you need and call it as you would any declared function. The
library links like any other of your own C, on the build line:

<!-- nish:ok -->
```ts
declare class OutI64 {
  value: i64;
}

declare function wc_new(mode: i32): CPtr | null;
declare function wc_total(c: CPtr, words: OutI64): i64;
declare function wc_free(c: CPtr): void;

export const WC_WORDS: i32 = 2;

export const count = (): i64 => {
  const c = wc_new(WC_WORDS);
  if (c === null) {
    return toI64(-1);
  }
  const words = new OutI64();
  const bytes = wc_total(c, words);
  wc_free(c);
  return bytes + words.value;
};
```

## What is not bound

The comment at the end of the module names every function, struct and macro
the command skipped, and why. Nothing is skipped silently. What it does not
bind today:

- a variadic function (`printf`), one that takes or returns a function
  pointer (a callback), and a `static` or `inline` function, which has no
  symbol to link;
- a function-like macro, or a macro whose value is not an integer or a
  string;
- a union, a struct with a bitfield or an array in it, a `long double`;
- `signed char` and `short`, which have no Nish width, and a plain `char`
  where the target makes it signed;
- a declaration from another header the first one includes, unless an
  override names it (below).

Write those by hand, beside the generated module, in a file of your own.

## Overrides: what the header cannot say

A header does not say whether a pointer may be `NULL`, whether a result must
be freed, or which parameter is a buffer's length. An overrides file, in JSON,
says so; pass it with `--overrides`:

```json wc.overrides.json
{
  "header": "wc.h",
  "allow": ["wc_*"],
  "functions": {
    "wc_new": { "return": "nonnull" },
    "wc_report": { "return": { "owned": "wc_free_report" } },
    "wc_feed": { "text": { "nullable": true } }
  }
}
```

- `header` is the header this file is for; a different header is refused.
- `allow` lists the names to bind, as globs (`*` matches any run of
  characters). Without it, every declaration in the header itself is bound;
  with it, only those names are, from whatever header declared them.
- `functions` sets, per function:
  - `"return": "nonnull"` or `"nullable"`, for a pointer result;
  - `"return": { "owned": "<free function>" }`, which records above the
    declaration which function frees the result;
  - per parameter, by name: `"nullable": true` or `false` for a pointer, and
    `"buffer": "<length parameter>"` (with `"readonly": true` for a `const`
    buffer), which binds a `void *` and its `size_t` length as a `u8[]`.

With this file, `wc_new` returns `CPtr`, `wc_report` carries the comment
`// The result is owned: free it with wc_free_report.`, and `wc_feed` takes
`string | null`. An override that names a function, a parameter or a free
function the header does not have is refused, so a renamed C function cannot
leave a stale override behind.

## Targets and the data model

A C type's size depends on the target: `long` is 64 bits on 64-bit Linux and
macOS and 32 bits on wasm32. The module records the target
and its data model in its first lines, and its `Regenerate:` line is the
command that wrote it. `--target <triple>` writes the module for another
target; without it, the module is for the machine you run the command on.

A build for a target with another data model refuses a generated module
(NL3059), instead of calling C with the wrong widths:

```console
$ nish c-import limits.h --target wasm32-unknown-unknown -o limits.ts
$ nish main.ts
limits.ts:3:16: error: this module was written by nish c-import for ILP32, and this build is LP64: ...
```

Regenerate the module with `--target` for that build, and keep one module per
data model if you build for both.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | the module was written |
| 1 | refused: the header or overrides file cannot be read, a scratch directory cannot be made beside the output, a path holds a quote, a backslash or a line break, clang rejected the header, or an override is wrong |
| 2 | usage: no header, no `-o`, an unknown flag or target |
| 3 | `clang` (or `CC`) cannot run |

On a refusal nothing is written, so a failed regeneration leaves the checked-in
module as it was.
