| [wp23-language-surface.md](wp23-language-surface.md) | Design note (proposed, not implemented, except the two items marked as landing): the language additions a corpus review turned up and no other package owns — non-generic `type` aliases and a numeric `enum` as pure checker work that changes no IR, module-level mutable state as the one functional gap (the `--json` object stage1 cannot emit) with the argument for threading a parameter instead, pairs and compile-time function parameters deferred to WP18's monomorphisation rather than given syntax, and `for...of` over a string, a string `switch` and `?.` declined with the rule each one breaks. |
| [wp24-async.md](wp24-async.md) | Design note (proposed and then declined): `async`/`await` — why the blocker is not the lowering but the absence of anything to wait for (the whole I/O surface is synchronous and there is no socket, timer or poller in either runtime), the two measurements of the lowering — LLVM 18 splitting a hand-written coroutine and eliding its frame entirely when the handle does not escape, and rustc using none of those intrinsics to build a 20-byte state machine that allocates nothing — what a suspend point would cost the attribute fixpoint and the arena, the asynchronous N-API export as the one item worth building and the only thing most askers actually want, what waiting forecloses (nothing: `async` and `await` are contextual in the grammar this compiler inherits, so no keyword needs reserving before the freeze) and which parts survive if it is ever built — `async`/`await` yes, the promise as a first-class value no — and the six refusals with the rule each one breaks. |
| [wp25-inheritance.md](wp25-inheritance.md) | The plan of record for removing inheritance and widening `implements` to a prefix check, and what it cost: what `extends` bought and why static dispatch made the third of those three things never work, the prefix rule that replaced it (same layout, same `bitcast`, same tail-padding reuse, pinned by the three layout classes that used to be derived), the three declared divergences the removal deleted — the virtual-vs-static dispatch entry that was the language's only knowing disagreement with JavaScript, the parity oracle's inheritance-cycle declaration and the last `tsc` divergence but one — the sixteen `reject_*` cases that collapse into two rules, and the zero derived classes in the 25,911 lines of `self/` that made it affordable. |
| [wp26-stdlib.md](wp26-stdlib.md) | The plan of record for the standard library, and what it cost: a `std/` module as Nish source compiled into whoever imports it rather than a linked artifact — measured, the attribute fixpoint proves `readnone` and `readonly` through it, a `std/` function inlines, and `--gc-sections` drops the seven exports a program does not call — against the compile time and the absent version of its own that buys; the rule that separates a module from a builtin (a builtin is for a syscall, a memory layout, or an effect the whole-program pass has to see, and everything the language can express is a module, which is why `std/text` added zero bytes of C); the five language restrictions the API had to absorb rather than choose — a function is never a value, no `try`/`catch` so an assertion records and answers a `boolean` because an out-of-range index panics, no generics when it was decided so one assertion per type (WP18 has since added them; §3c says why the API stays), no optional parameters, and one flat symbol namespace shared with the importer; the number-mode rule and the half of it `std/text` does not keep; the `tests/link/` case as the only thing that puts a module in front of both compilers, and why `std/` is deliberately not in `CORPUS_DIRS`; how the third module (`std/json`, one flat object read by field) reads against the rule that admits a module at all, and the assertions `std/testing` grew once two harnesses had written them by hand; and the seven open questions, from the bare specifier WP21 would buy to whether a library may allocate when it cannot know its caller's arena discipline. |
| [wp27-ffi.md](wp27-ffi.md) | Design note (S1 and S2 built, S3 onward proposal): calling C from Nish through TypeScript's own `declare function` syntax — why a foreign call is the one place the whole-program fixpoint has to be told rather than shown, the scalar-only first stage, `CPtr` as the opaque pointer a C function hands back, and the question §3 leaves standing over every later stage: whether widening the FFI past scalars and opaque pointers should happen at all, given that every attribute this compiler emits is a promise a foreign callee never made. |
| [wp28-compatibility-mode.md](wp28-compatibility-mode.md) | Design note (proposed, nothing built, one of two gating spikes measured): a compatibility dialect that accepts ordinary statically typed TypeScript so a codebase can be ported first and made fast afterwards — the line that decides what may enter it (layout stays fixed at compile time, so the cost is attributes rather than the object model, and the dynamic tier is refused in every dialect permanently), the existing `performance` class as the migration dashboard, the erasure invariant that makes the mode a provable no-op until it is used, the flag surface regrouped into dialect / build / output with one allow-list flag that a team ratchets down in `package.json`, why compat implies `--number-mode f64`, what one opaque callee actually costs — 1.26x to 1.40x for the lost inlining, nothing at all for the frontend facts it strips from every transitive caller, and 8.76x for the escape proof it takes away, which is why the migration report leads with the arena rather than the attribute — and `async` in three lowerings: why wp24's refusal of erasure survives, the one-live-promise rule that makes erasure exact rather than a lie, and the non-interference proof that turns the same `Promise.all` into real parallelism under `--async-model threads`, sequenced behind WP20's T1 and T2 because notation is the wrong thing to design an engine through. |
| [wp29-thread-surface.md](wp29-thread-surface.md) | Design note (proposed, nothing built): the thread surface, decided by the constraint that a Nish program must be legal TypeScript — no new keyword is available, so every construct is a call except *lifetime*, where `using` is the one block-scoped cleanup form the language has and a scoped thread group is exactly that. Rust's scoped threads spelled `using` (which makes join-on-every-path a property of the construct and deletes wp20 T1's analysis and diagnostic), a `Mutex<T>` that owns the data it protects, Rayon-shaped data parallelism whose disjointness is the intrinsic's rather than a proof obligation, and race freedom from the attribute fixpoint rather than from `Send`/`Sync` bounds or a runtime detector; what to take from Rust and from Go and what to refuse from each; the whole surface run through `tsc --strict` before being proposed, clean at `"lib": ["ES2022"]` once the declaration file carries the disposable protocol itself, with the two Phase 0 rules that file breaks named rather than hidden; the argument for reversing wp20's stage order; and the one warning this compiler can give that neither Rayon nor a `go` statement can. |
The remaining semantic changes after WP13 (checked integer division,
ECMAScript `Math.pow`, numeric-only ordering, `?.`/`??` rejected,
`-2147483648`) have no design note of their own; LANGUAGE.md and
[CHANGELOG.md](../CHANGELOG.md) describe them.

## Tooling for these docs

- `docs/cookbook/regen.sh` rebuilds every IR listing in IR_COOKBOOK.md from
  `docs/cookbook/*.ts`; `--check` fails when the doc is stale.
- `node docs/check-links.mjs` verifies every relative link and heading
  anchor in `README.md`, `CHANGELOG.md`, and `docs/**/*.md`.
