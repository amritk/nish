when the package landed. They are historical records, not the reference;
where they disagree with LANGUAGE.md, LANGUAGE.md wins.

| [wp18-generics.md](wp18-generics.md) | Design note (proposed, not yet implemented): user generics by monomorphisation — the surface and why inference rather than type arguments at a call site, how an instantiation is discovered and where its one definition goes, the mangling, the rule that makes monomorphisation terminate, the worked IR for `identity<T>` and `Box<T>`, every existing feature as a rule, the diagnostics, and why Nish-0 does not adopt them. |
| [wp19-stage0-retirement.md](wp19-stage0-retirement.md) | The plan for the day stage0 is deleted rather than frozen: how rustc, Go, GCC and Zig each answered "what compiles the compiler", the four things stage0 still owns, the six gates that must close first, the builtins they need, and what the retirement costs. |
| [wp20-threads.md](wp20-threads.md) | Design note (proposed, not yet implemented): true multithreading — why the answer is 1:1 OS threads with data races rejected at compile time rather than goroutines, what the absence of mutable globals and closures already buys, the global arena and the inlined bump allocator as the blocker, and the five stages from a thread-local arena to data parallelism. |
| [wp21-packages.md](wp21-packages.md) | Design note (proposed, not yet implemented, and rough): packages — why an Nish consumer takes a dependency as source while a JavaScript or C host takes a built artifact, the `exports` condition map that states both, the four reasons a compiled library cannot keep the whole-program facts, how a package says it is Nish — the number mode rides in the condition and nothing else needs a manifest — the flat symbol namespace as the one hard blocker, and the five stages. |
| [wp22-arrow-functions.md](wp22-arrow-functions.md) | Design note (proposed, not yet implemented): arrow functions become how Nish declares a function and `function` becomes legacy — why the change cannot alter a single byte of IR (so the goldens verify the migration rather than being work it creates), the two checker rules that accept an arrow without admitting function values, the concise body as the one genuinely new shape, class methods as the permanent exception, and the four stages the bootstrap forces. |
| [wp23-language-surface.md](wp23-language-surface.md) | Design note (proposed, not implemented, except the two items marked as landing): the language additions a corpus review turned up and no other package owns — non-generic `type` aliases and a numeric `enum` as pure checker work that changes no IR, module-level mutable state as the one functional gap (the `--json` object stage1 cannot emit) with the argument for threading a parameter instead, pairs and compile-time function parameters deferred to WP18's monomorphisation rather than given syntax, and `for...of` over a string, a string `switch` and `?.` declined with the rule each one breaks. |
| [wp24-async.md](wp24-async.md) | Design note (proposed, declined, and re-opened by the server requirement): `async`/`await` — why the blocker was never the lowering but the absence of anything to wait for, the two measurements of the lowering (LLVM 18 splitting a hand-written coroutine and eliding its frame entirely when the handle does not escape, and rustc using none of those intrinsics to build a 20-byte state machine that allocates nothing — the shape to copy), what a suspend point costs the attribute fixpoint, the arena, the wasm twin and the differential oracle, the asynchronous N-API export as the one item worth building regardless and the only thing most askers actually want, the trigger §8 wrote down so a future reader could check it rather than re-argue the case — *someone wants to write a server* — and which parts survive when it fires: `async`/`await` yes, the promise as a first-class value no. The staging is now [wp26](wp26-io-and-servers.md)'s. |
| [wp25-inheritance.md](wp25-inheritance.md) | The plan of record for removing inheritance and widening `implements` to a prefix check, and what it cost: what `extends` bought and why static dispatch made the third of those three things never work, the prefix rule that replaced it (same layout, same `bitcast`, same tail-padding reuse, pinned by the three layout classes that used to be derived), the three declared divergences the removal deleted — the virtual-vs-static dispatch entry that was the language's only knowing disagreement with JavaScript, the parity oracle's inheritance-cycle declaration and the last `tsc` divergence but one — the sixteen `reject_*` cases that collapse into two rules, and the zero derived classes in the 25,911 lines of `self/` that made it affordable. |
| [wp26-io-and-servers.md](wp26-io-and-servers.md) | Design note (proposed, not yet implemented): sockets, the reactor, and what a server needs before `async` means anything — the package [wp24](wp24-async.md) §6 called A2 and left unowned, now that Nish is to be used for servers. The four stages, ordered so that the **first one ships a server and the syntax is last**: blocking sockets on a WP20 thread pool with no language change at all, then the reactor (poller, timers, a monotonic clock) still with no language surface, then `async`/`await` over it gated on beating the reactor's measured connections per second, then futures as data after WP18. Four measured findings that move other packages: the runtime budget is spent (4,088 of 4,096, against three stale figures in three notes), WP20 T1's structured join cannot express an accept loop, a blocking `accept` has no Node twin and so WP13 owes a written decision, and the arena is already the right per-request memory model. Eight refusals with the rule each one breaks, TLS and `io_uring` among them. |
The remaining semantic changes after WP13 (checked integer division,
ECMAScript `Math.pow`, numeric-only ordering, `?.`/`??` rejected,
`-2147483648`) have no design note of their own; LANGUAGE.md and
[CHANGELOG.md](../CHANGELOG.md) describe them.

## Tooling for these docs

- `docs/cookbook/regen.sh` rebuilds every IR listing in IR_COOKBOOK.md from
  `docs/cookbook/*.ts`; `--check` fails when the doc is stale.
- `node docs/check-links.mjs` verifies every relative link and heading
  anchor in `README.md`, `CHANGELOG.md`, and `docs/**/*.md`.
