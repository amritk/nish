# WP34 wave 0: N2 → N6 → N3

## Context

[docs/wp34-hosting-cs.md](../../docs/wp34-hosting-cs.md) §4 lists what the compiler owes the network stack before the stack's lanes can use it. This run builds three of those items: N2 (byte plumbing), N6 (constant time) and N3 (clock, entropy, file times, signals). N1 and N5 are not in this run. The note is not normative; where it and [docs/LANGUAGE.md](../../docs/LANGUAGE.md) disagree, LANGUAGE.md wins, and each stage lands its rule there in the same PR.

## Approach

- **Sequential, one PR each, in the order asked: N2, then N6, then N3.** All three add builtins, so all three touch the same registry: [src/builtins.ts](../../src/builtins.ts), [src/emit-builtins.ts](../../src/emit-builtins.ts), [src/codes.ts](../../src/codes.ts), [runtime/nish.d.ts](../../runtime/nish.d.ts), [runtime/nish.mjs](../../runtime/nish.mjs), LANGUAGE.md §Builtins and the cookbook. Running them at once would produce three PRs conflicting in every one of those files. Each stage starts from `main` after the previous one merges.
- **Every stage ships the construct checklist** ([docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) → "How to add a construct"). That means a golden `.ll`, an `llvm-as` pass, a native round trip with expected stdout, at least one `reject_*` negative with a registry code, the LANGUAGE.md rule, a cookbook entry, and the TypeScript reading (WP33 class A/B/C) with Node agreeing where the class says it does.
- **Rolling freeze.** `src/` may not *use* any of these builtins in its own source until a release carries them. This run cuts no release; the Release PR stays the owner's merge.
- **The commit subject is the changelog.** Each PR title is the stage title above, and must pass `node scripts/changelog-gen.mjs --check-subject`. The body carries `Refs:` and `Tests:` trailers.

**Owns: every stage is `src/**`, `runtime/**`, `tests/**`, `std/**`, `examples/**`, `docs/LANGUAGE.md`, `docs/AI.md`, `docs/IR_COOKBOOK.md`, `docs/cookbook/**`, `docs/RUN_UNDER_NODE.md`, `docs/wp33-round-trip.md`, `docs/wp34-hosting-cs.md`, `docs/MASTER_PLAN.md`, `llms.txt`, `THIRD_PARTY_NOTICES.md`, plus regenerated stores (`tests/self/goldens/*`, `tests/perf-baseline.json`, `bench/instructions.json`).** The stages share these globs, and that is safe only because they never run at once. No stage touches `.github/**`, `package.json`, `package-lock.json`, `biome.json`, `tsconfig.json`, `knip.json`, or anything under `scripts/` that releases or publishes. `CHANGELOG.md` is generated from commits.

## N2 — byte plumbing

**Owns:** as above (shared, sequential).

### Rules
- `dst.set(src: u8[], offset?: i32)` copies all of `src` into `dst` starting at `offset` (default 0). Its meaning is `TypedArray.prototype.set`'s: `offset + src.length > dst.length` fails the way an out-of-range index does, and `dst === src` or an overlapping copy behaves as if `src` were copied first. Decide whether `set` is admitted on every numeric element type or only on `u8[]`, and say so in the rule.
- `fill(value, start?, end?)`: `TypedArray.prototype.fill`'s meaning, including negative `start`/`end` if the rule admits them. If it does not, it refuses them with a code.
- The TypeScript reading: the note calls `set` class A (identical). If Nish's `u8[]` runs under Node as a plain `Array`, `set` needs a shim in `nish.mjs`. Record the class honestly in [docs/wp33-round-trip.md](../../docs/wp33-round-trip.md) if it is not A.
- A window into a buffer stays `(buf, off, len)` by convention. No view type (note §4 N2).

### set
Lower to `llvm.memmove`. Lower to `llvm.memcpy` only when the checker *proves* the two operands are different arrays, and record that proof in a side table; the emitter never re-derives it. The whole-program alias facts in [src/escape.ts](../../src/escape.ts) and [src/tbaa.ts](../../src/tbaa.ts) are the place to look, and "not proven" means `memmove`. Show both IR shapes in the PR body.

### fill
For `u8[]`, `llvm.memset`. For wider element types, a store loop LLVM can vectorise, or `memset` when the value is a zero bit pattern.

### readFileBytesSync
`readFileBytesSync(path: string): u8[] | null`, exported from `nish:fs` and declared ambiently, beside `readFileSyncOrNull`. Binary-safe: zero bytes and bytes ≥ 0x80 survive, with no UTF-8 validation. Missing or unreadable → `null`. The C goes beside `readFileSyncOrNull` in [runtime/runtime-os.c](../../runtime/runtime-os.c) if it fits the ceiling (see N3 → Where the C goes, which applies here too). On `wasm` it is refused as `readFileSync` is.

### Tests
- `tests/cases/bytes_set_*`, `bytes_fill_*`, `bytes_read_*`: goldens plus expected stdout. Cover a forward overlap, a backward overlap, self-copy, disjoint arrays (the `memcpy` IR), offset at the end, an out-of-range offset (the panic), fill with and without a range, and a binary file read (with a fixture committed under `tests/`) plus a missing file.
- Each program is also run under Node (`node --experimental-strip-types --import ./runtime/nish.mjs`), and stdout must match. This follows the existing differential/unmodified harness.
- `reject_*` cases for each refused form, with codes from the next free numbers in [src/codes.ts](../../src/codes.ts).
- A cookbook entry under [docs/cookbook](../../docs/cookbook) (regenerated with `bash docs/cookbook/regen.sh`), and a line in [docs/AI.md](../../docs/AI.md).

## N6 — constant time

**Owns:** as above (shared, sequential). Starts from `main` after N2 merges.

### Rules
- `ctSelect(mask, a, b)`: `mask` is all-ones or all-zero of the operands' type. It returns `a` when the mask is all-ones and `b` when it is zero, as `(a & mask) | (b & ~mask)`. `ctEq(a, b)` returns that mask type: all-ones if equal, else zero. Both are over `u32` and over `u64`. Decide whether they are ambient globals or a builtin module (`nish:ct`) by the precedent LANGUAGE.md §Builtin modules sets, and write the decision into the rule.
- The TypeScript reading is class A for `u32`, with a pure shim in `nish.mjs` using `>>> 0` arithmetic. For `u64`, the shim uses `BigInt` if that is how `u64` runs under Node today; follow what the existing `u64` reading does.
- The rule states plainly what the barrier promises (no branch and no secret-indexed load *in these primitives*) and what it does not (the caller's own code).

### Lowering
Emit the bitwise form, then hide the mask from the optimiser so it cannot turn `select`/`and`/`or` back into a branch. The standard barrier is an empty inline-asm `asm "", "=r,0"` on the mask (the BoringSSL / `subtle` crate idiom), but choose whichever the evidence supports. [src/attributes.ts](../../src/attributes.ts) may not mark the call site with anything the fixpoint does not justify. Check the result at `-O2` on x86-64 and aarch64 (`llc -mtriple`), and on `wasm32` if the target admits these builtins.

### The assembly check
A new section in [tests/run.js](../../tests/run.js), run by `npm test` and therefore by CI with no workflow edit. It compiles `tests/ct/*.ts` to `.s` for x86-64 and aarch64 and, inside each ct function (found by symbol), refuses:
- any conditional branch (`j<cc>` other than `jmp`, `b.<cond>`, `cbz`/`cbnz`/`tbz`/`tbnz`);
- any load whose address depends on a value named secret by the fixture.

It includes one deliberately branchy fixture that the check must *refuse*, so a check that silently matches nothing fails. The fixtures cover `ctSelect` and `ctEq` on both widths, and a 32-byte MAC compare loop over `u8[]` built from them, which K1 will reuse.

The dudect-style weekly timing run the note mentions needs a scheduled workflow. It is **not** in this run (see Out of scope).

### Tests
Goldens and native round trips over a table of inputs (equal, unequal, all-ones, zero, high-bit), agreeing with Node. `reject_*` cases for the wrong operand type, mixed widths, and a non-integer mask. A cookbook entry and an AI.md line.

## N3 — clock, entropy, file times, signals

**Owns:** as above (shared, sequential). Starts from `main` after N6 merges.

### Where the C goes
Before adding anything, measure. `runtime-os.c` holds 1,190 of its 1,280-byte `.text` ceiling ([docs/MASTER_PLAN.md](../../docs/MASTER_PLAN.md) §2, measured by `tests/run.js`), and N2's `readFileBytesSync` has spent some of the rest. If the four additions do not fit, split them into a new runtime file with its own measured ceiling, on the precedent that created `runtime-os.c`. **Never raise an existing ceiling.** Record the numbers in MASTER_PLAN §2 and in the PR body.

### Date.now
`Date.now(): f64`, milliseconds since the epoch from `clock_gettime(CLOCK_REALTIME)`. Class A under Node. Only `Date.now` is admitted: `new Date()` and every other `Date` member are refused with a code that names the rule.

### getRandomValues
`crypto.getRandomValues(bytes: u8[]): void` (or returning the array, as the Web API does; decide in the rule). It uses `getrandom(2)` on Linux, looping over `EINTR` and short reads, and `getentropy(3)` in 256-byte chunks on macOS. Failure panics, and never falls back to a weaker source. The Web API refuses more than 65,536 bytes; decide whether Nish matches that and say so. Class A under Node, whose global `crypto` exists.

### statMtimeSync
`statMtimeSync(path: string): f64 | null`, the modification time in milliseconds (with sub-millisecond precision where the platform gives it), or `null` when the file cannot be stat'd. It lives in `nish:fs` and the ambient globals, beside the other `fs` builtins. The `nish.mjs` reading is `fs.statSync(p, {throwIfNoEntry:false})?.mtimeMs ?? null`.

### Signals
A descriptor the loop can wait on, not a handler. For example:

```ts
import { signalFd, readSignal } from "nish:process"; // names decided in the rule
const fd: i32 = signalFd();       // blocks SIGTERM+SIGINT, returns a readable fd
// … poll/epoll on fd (N5), or a blocking read today …
const sig: i32 = readSignal(fd);  // 15 or 2; blocks until one arrives
```

On Linux, `signalfd`, with the signals blocked in the process mask. On macOS, a self-pipe written from a `sigaction` handler in the runtime's C, where the handler is C and not a Nish function value. The TypeScript reading is class C: under Node, `process.on('SIGTERM')`. Write down the shim, or the reason no faithful one exists, in the WP33 ledger. N5 (not in this run) will consume the fd; this stage proves it with a blocking read.

### Tests
- `os_now_*`: a program prints `Date.now()`, and the harness checks it is within 1 s of the harness's own clock.
- `os_random_*`: two calls differ; two runs differ; length 0 is fine; the Web API limit behaves as the rule says.
- `os_mtime_*`: the harness sets a file's mtime with `fs.utimesSync` and the program prints what it reads; a missing file gives `null`.
- `os_signal_*`: a Node driver in `tests/` spawns the program, waits for a ready line, sends SIGTERM (and in a second case SIGINT), and expects the program to print the signal number and exit 0.
- `reject_*` for each refused form, including `new Date()`. A cookbook entry, an AI.md line.
- Mark N2, N3 and N6 as built in [docs/wp34-hosting-cs.md](../../docs/wp34-hosting-cs.md), naming their PRs.

## Out of scope

- N1 (exported enums and aliases), N5 (sockets and the loop), N9, and every K/T/H/Q/R/A lane.
- **N6's weekly dudect timing job**: it needs a scheduled `.github/workflows/` job, which the merge gate treats as a sensitive path. It becomes a follow-up issue filed at close-out.
- A view type over `u8[]`; wide multiplication; `Date` beyond `now`; signals other than SIGTERM and SIGINT; any of this on `wasm` beyond a coded refusal.
- Cutting a release. The Release PR stays the owner's.
