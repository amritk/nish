# WP49 stage 5 — the executor, serve, async fetch and the async Postgres pool

## Context

Stage 4 (#1160, #1202, #1212) compiles `async`: each function that awaits is a frame plus `@f.resume`, and [src/emit-async.ts](../../src/emit-async.ts) appends an in-process driver (`@nish.async.enqueue`, `.step`, `.drain`, a `malloc`ed node per `spawn`, `llvm.trap` on a stuck queue). Nothing pends on the outside world, so three things are sound only for now ([WP49, "Stage 4, part 2"](../../docs/wp49-async-server.md#stage-4-part-2-the-lowering)): the arena is a stack, `spawn` copies argument values but not what they point to, and a synchronous `main` drains its tasks only at exit.

Every runtime unit is linked into every program today ([scripts/build.sh](../../scripts/build.sh) `halves`, [src/compile.ts](../../src/compile.ts) `--runtime-objects`). The executor is the first unit that must be linked only when used.

## Approach

- **Order.** `executor` first, alone. `async-fetch` and `async-serve-pg` start when it merges and run in parallel. `cancellation` starts when both merge. Every later stage consumes `nish:async`'s three primitives, so none can start before the executor lands.
- **The primitives answer a failure from day one.** `readable`, `writable` and `sleep` return a value that can say "did not happen" (a `boolean`, or a `Result`, the executor's choice, recorded in LANGUAGE.md). Cancellation then changes what they answer, never their signatures.
- **The rolling freeze.** `src/` may change but must not *use* `async`, which the seed (0.36.0) does not ship as a runtime feature. `std/` and tests may.
- **`--profile wasm` still refuses `async`** (NL2652). No stage touches that refusal except to keep its tests green.

## Executor

**Owns:** `src/**`, `runtime/runtime-async.c`, `runtime/runtime-region.c`, `runtime/runtime-net.c`, `runtime/nish.h`, `runtime/nish.d.ts`, `runtime/async.mjs`, `runtime/async.d.mts`, `scripts/build.sh`, `scripts/fuzz.sh`, `tests/runtime-budgets.js`, `tests/cases/*async*`, `tests/cases/*sleep*`, `tests/emit-ts/async/**`, `tests/link/async_*/**`, `tests/run.js`, `tests/shard-costs.json`, `tests/differential/**`, `docs/security/async.md`, `docs/security/README.md`, `docs/security/runtime.md`, `docs/LANGUAGE.md`, `docs/IR_COOKBOOK.md`, `docs/guide/language/async.md`, `docs/wp49-async-server.md`, `docs/reference/**`, `tests/self/goldens/checked/**`

- **runtime/runtime-async.c.** One executor per process on the thread that runs `main` (§4, D2). A ready list, an epoll set (kqueue on Darwin) built on the same calls as `nish_poll_wait`, a binary-heap timer list keyed by deadline, and a wake-up path for a task made ready by another task. Every registration carries `(task index, generation)`; a completion whose generation no longer matches its slot is dropped (the `nish/net/handler` rule). Resume order: ready tasks in the order the kernel reports them, then expired timers by deadline (§2, "Where it is not Node").
- **nish:async.** `readable(fd)`, `writable(fd)`, `sleep(ms)` are `async` builtins: awaiting one parks the current task on the executor and returns `PENDING` through the frame machinery stage 4 already emits. Calling one outside `await`, `spawn` or `awaitAll` is refused by the existing NL2644/NL2645 rules; add a negative test that proves it.
- **The slab.** One slab per spawned kind, sized from the whole-program frame mark stage 4 already writes (`BYTES_MARK`), growing to the peak in flight and then reused: no `malloc` per `spawn` once warm. The generated `switch` on kind stays; no function pointer.
- **No trap.** When nothing is ready and something waits, the loop blocks in the kernel until the earliest timer or a readiness event. When nothing waits and nothing is ready, the loop ends. A task that waits on an fd nobody will ever make ready blocks forever, as a blocking read would; say so in the security record.
- **Linked only when used.** A program with no `async` function writes the same `.ll` as `main` (the D1 diff over every no-async `tests/cases`, reported as a count in the PR body) and its linked binary has no `nish_async_*` symbol. How (link the object only when the module references it, an archive member, or `--gc-sections`) is the executor's choice; record it in WP49.
- **--emit-ts.** `runtime/async.mjs` gets `readable`, `writable` and `sleep` over Node's own loop (sleep over `setTimeout`; readable and writable over whatever `runtime/node.mjs` gives the `nish:net` poll calls, or a documented refusal if there is no fd under Node). Types in `runtime/async.d.mts`.
- **Docs.** `docs/security/async.md` (scope `runtime/runtime-async.c` and the emitted driver; findings: late completion, generation wrap, timer overflow on a huge `ms`, fd reuse after close, starvation), its row in `docs/security/README.md`. LANGUAGE.md's "Where it is not Node" gains the real-wait resume order. The guide page [docs/guide/language/async.md](../../docs/guide/language/async.md) shows `sleep` and a socket wait. WP49 "Stage 4, part 2" gets a "Stage 5, part 1" section saying the three debts are paid and how.

## The three debts

| Debt | What the executor does |
| --- | --- |
| (a) the arena is a stack | each task gets its own region from `runtime-region.c`; the executor enters it on resume and leaves it on suspend, and frees it when the task ends, so mark and release are contiguous inside a task again (§5). A warm server makes no `malloc` per task: freed region chunks go to the free list |
| (b) spawn's arguments must outlive the spawner | what a `spawn` argument points to (a string, an array, an object) is copied into the new task's region, or the checker refuses an argument it cannot copy, with a code and a negative test; the executor picks one and records it in LANGUAGE.md |
| (c) a synchronous `main` drains only at exit | the C entry runs the loop after a plain `main` returns too, before exit, so a task spawned from a synchronous `main` that waits still finishes |

Each debt gets a test that fails on `main`'s driver (or would, once a task can wait) and passes here.

## Async fetch

**Owns:** `std/net/fetch.ts`, `std/net/upstream.ts`, `std/net/http1-client-codec.ts`, `std/net/outbound.ts`, `tests/link/net_fetch*/**`, `tests/link/net_http_fetch*/**`, `docs/security/fetch.md`, `docs/security/upstream.md`, `docs/guide/using-nish/http-client.md`, `docs/guide/using-nish/calling-services.md`, `docs/wp49-async-server.md`, `docs/reference/**`, `tests/self/goldens/checked/**`, `tests/shard-costs.json` (its own rows only)

- **The body shape (decided at plan sign-off).** §2's example writes `await res.text()`, but NL1063 refuses `async` on a method (a task keeps no `this`). **The owner chose an eager body with a cap.** `fetch` reads the whole body before it answers, up to `RequestInit.maxBodyBytes` (the same 256 MiB default and the same `HTTP_E_BODY_TOO_LARGE` as `HttpOptions`), and `res.text()` / `res.bytes()` are plain methods: `const body = res.text()`. Why: it is what `fetchSync` already does by default; a response then holds no connection, so it can be kept after the task's next `await` and its connection goes back to the pool at once; and no reader object has to carry a parked connection across tasks. The alternative, a free `async` reader (`await readText(res)`), streams but adds a second wait and a response that pins a pooled connection. Record the choice and the reason in WP49 §8 and rewrite §2's example to match.
- **`fetch(url: string, init: RequestInit | null = null): Promise<FetchResponse | null>`** or a `Result` (the worker picks one shape and states it), beside `fetchSync` in `nish/net/fetch`. It drives `nish/net/http1-client-codec` and keeps connections in `Upstream`'s pool (one pool per origin, created on first use, capped), and waits with `readable`/`writable`. DNS goes through the existing resolver path `fetchSync` uses; if that path blocks, say so in the record rather than leave it unstated.
- **Same policy and errors.** `OutboundPolicy`, `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` (`httpChooseProxy`, `httpProxyFor`), redirects and the `HTTP_E_*` codes behave as in `fetchSync`; share code with it rather than copy it.
- **TLS.** If `fetchSync`'s https path cannot be driven without blocking in this stage, `fetch` of an `https:` URL answers a stated error, recorded in `docs/security/fetch.md` and the guide page, not a silent block.

The rule to design, write down first and then build (the worker may refine it in the WP49 section and say why):

- **Function arguments.** A capture-free function argument to a spawned call is spawnable: it is lifted at compile time and holds no memory. The task kind is instantiated per function argument, as `serve` is instantiated per `handle`.
- **Owned objects.** An object, array, `Map` or `Set` argument is spawnable when it is the spawner's: allocated before the `spawn` in a scope that is still open, never from a `using arena()` block or a scoped loop pass that ends first (the existing escape machinery decides this; an argument it cannot prove is refused with a code). Its storage must outlive every task holding it: a function that spawns with such an argument does not release its automatic scope under it (it is an escape, as `allocLeaks` is), so it lives until `nish_free_arena` after the drain. Say what that costs a long-running spawner and why it is bounded (the objects are made once, before the loop).
- **What a task may do to it.** Seed the spawned function's object parameters as OUTER in the region walk, as `regionWith` does: reading is free, scalar fields and elements may be written, storing task-region memory into it is NL2609 and growing it (`push`, `Map.set`, `Set.add`) is NL2615. A task therefore mutates shared state only in place, which is how the handler, the router and the carrier are already written (fixed slots, allocation-free once warm).
- **Strings.** A `string` argument stays copied. A string stored into a shared object from a task stays refused (NL2609).
- **Nothing else changes.** The NL2673 refusal stays for every other type; a program with no `async` is byte-identical; NL2652 stays.

## Serve

**Owns:** `std/net/serve.ts`, `std/net/handler.ts`, `std/net/http1-server.ts`, `std/net/router.ts`, `std/README.md`, `docs/AI.md`, `tests/link/net_serve*/**`, `docs/security/serve.md`, `docs/security/handler.md`, `docs/security/README.md` (its own row), `docs/guide/using-nish/async-server.md`, `docs/guide/using-nish/api-server.md`, `docs/guide/index.md`, `scalar.config.json`, `examples/serve*.ts`, `docs/reference/**`, `tests/self/goldens/checked/**`, `tests/shard-costs.json` (its own rows only)

- **`serve(port, router, limits, handle)`** as in WP49 §2's handler example: `handle` is a function-typed parameter answering `Promise<Response>`; `serve` accepts, parses with the HTTP/1.1 codec, routes with `nish/net/router`, and spawns one task per request, passing `handle`, the server's own state object and the request's slot and generation (spawn-reach's rule). Each task runs in its own region; its response is written back on the connection in request order, so pipelining stays correct. A task gets its own `params` scratch, since `Router.match` is one at a time. `ServeLimits` caps connections, requests in flight, header and body sizes and holds a per-request deadline (used by cancellation).
- **No allocation per request once warm**: the slab, the region free list and the connection buffers are reused. `Arena.used()` flat over thousands of pipelined requests is the test.

**Owns:** `std/net/postgres-async.ts`, `std/net/postgres-carrier.ts`, `std/net/postgres.ts`, `tests/link/std_postgres*/**`, `tests/postgres/**`, `docs/security/postgres.md`, `docs/security/README.md` (its own row), `docs/guide/using-nish/postgres.md`, `docs/reference/**`, `tests/self/goldens/checked/**`, `tests/shard-costs.json` (its own rows only)

- `std/net/postgres-async.ts`: a pool over `PgCarrier` that `main` creates once and passes to spawned tasks (spawn-reach's rule). A method cannot be `async` (NL1063), so the API is free functions, `const rows = await pgQuery(pool, ...)` or the carrier's prepared-statement shape. It waits with `readable`/`writable` on the carrier's sockets, batches as the carrier does, and answers the carrier's failure codes. Tests use the loopback setup the `std_postgres_carrier` tests already use.
- Records: `docs/security/postgres.md`'s scope gains `postgres-async.ts`; `docs/guide/using-nish/postgres.md` gains the async pool.

## Cancellation

**Owns:** `src/**`, `runtime/runtime-async.c`, `std/net/serve.ts`, `std/net/fetch.ts`, `std/net/postgres-async.ts`, `std/net/handler.ts`, `tests/link/net_serve*/**`, `tests/link/net_fetch*/**`, `tests/link/std_postgres*/**`, `tests/link/net_serve_pg*/**`, `tests/link/async_*/**`, `tests/cases/*async*`, `tests/run.js`, `tests/shard-costs.json`, `docs/security/**`, `docs/LANGUAGE.md`, `docs/guide/**`, `docs/wp49-async-server.md`, `docs/reference/**`, `tests/self/goldens/checked/**`

- A task is cancelled when its client hangs up (the executor sees `EPOLLRDHUP`/`EV_EOF` on the request's connection), its `ServeLimits` deadline passes, or the server shuts down (D3). The executor sets a flag in the task's slot; the wait it is parked on, and every later `readable`/`writable`/`sleep`, answers its failure at once. `fetch` and the Postgres pool turn that into their own failure (`HTTP_E_*`, the carrier's code), so the handler sees an ordinary failed call. Nothing unwinds: the task runs to its end, `using` bindings dispose, and the region is freed.
- The same deadline gives async `fetch` a bound on each wait (`connectTimeoutMs`, `readTimeoutMs`, `totalTimeoutMs`), closing HF-10 in `docs/security/fetch.md`.
- An end-to-end test: a `serve` handler awaits a Postgres query through the async pool (`tests/link/net_serve_pg`).
- Tests: a client that sends a request and hangs up while the handler waits on a slow upstream; a handler past its deadline. Each asserts the handler's code after the failed `await` ran, a `using` disposer printed, and `Arena.used()` / the region count came back to where it started.

## Acceptance

Derived from the request, checked against `main` after the last merge:

1. A program with no `async` function compiles to the same `.ll` as before stage 5 and its binary contains no executor symbol.
2. `await sleep(50)` in an async `main` returns after at least 50 ms, and two spawned tasks sleeping 30 ms and 10 ms finish shortest first.
3. A task awaiting `readable(fd)` on a pipe resumes when another task writes to it, without a trap or a busy loop.
4. A task spawned from a synchronous `main` that waits still runs to its end before the process exits.
5. A string built by the spawner and passed to `spawn` is intact when the task reads it after the spawner has returned and the task has waited.
6. A CLI program's `await fetch(url)` against a loopback server prints the body, and `awaitAll(fetch(slow), fetch(fast))` completes the fast one while the slow one is still pending.
7. `Arena.used()` is flat over thousands of async fetches and over thousands of pipelined requests to a `serve` server.
8. `serve(port, router, limits, handle)` answers routed requests, 404 and 405, pipelined and in order, and a handler can `await` a Postgres query through the async pool.
9. A client hanging up mid-request, or a handler passing its deadline, makes the handler's pending `await` answer its failure; the handler finishes, its `using` disposes and its region is freed.
10. `--profile wasm` still refuses an `async` program with NL2652.
11. Every new attacker-facing file (`runtime/runtime-async.c`, `std/net/serve.ts`, `std/net/postgres-async.ts`) is in a `docs/security/` record's scope, and `node scripts/security-scope.mjs` passes; the guide has pages for the executor primitives, async fetch and `serve`.

Added when the owner chose option (a) on #1278 (2026-11-08):

12. `spawn(task(handle, state, i))` compiles when `handle` is a function argument and `state` an object the spawner made; the task sees and updates `state`'s number fields, and the spawner's object is intact after the spawner returns while tasks still run.
13. A task that stores memory it allocated (a string, array or object) into a spawned object, or grows one of its arrays or maps, is refused at compile time with a code.
