## Approach

| Decision | Choice | Why |
| --- | --- | --- |
| Display vs linkage | Diagnostics, the checked dump, DWARF `name` and header/.d.ts comments use the source spelling (`Box<i32>`). Symbols, `%struct` names, `linkageName` and C `NISH_SYMBOL` keep the mangled spelling. | §6.7, and what clang does for a C++ template. It costs no IR byte outside `-g`. |
| C function names | Extend the `nish_gen_` escape that makes `cStructName` injective to function symbols that contain `$`. `nish_` is already reserved for user functions and classes, so the result cannot collide with a user name. A remaining `.`-only collision (`Point.shifted` vs `Point_shifted`) is detected and refused with a clear message, not silently duplicated. | §14 q4 said "a rename rather than a refusal" where one is possible. |
| JS names | One identifier-safe, injective spelling per exported instantiation, shared by `.d.ts`, the wasm loader and N-API. The worker picks the encoding (for example, the C name) and records the choice in the PR body, for the docs stage. The rule must hold for array, readonly-array, nullable and Result arguments, which put `.` in the mangling. | §6.8 assumed `$` is the only special character, and it is not. |
| Unused exported template | An error only when a sidecar flag is given (§8 message 9, verbatim spirit), and a new NL4xxx code. With no sidecar flag, nothing changes. | §6.8 |
| Differential rewrite | **Out of scope.** §12's "one JS function per instantiation" needed the live rewriter, which R6 deleted. The docs stage records it as superseded, in the same words `unfrozen.txt` uses. | wp19 §6: the way back is a stage1-typed rewriter, which is its own package. |
| Constraint identity | Compare the struct's `TypeTable` id, or its declaring origin, instead of its name. | #161. Lifting the imported-`implements` refusal (NL2079) stays out. |

`self/` does not use generics (the rolling freeze), so the bootstrap input is unchanged and its fixed point must hold.

WP18 deferred this (§2, §13, §14 q7) and the owner has asked for it now. It is a real design step, so the worker writes §15.8 **first** and makes the code match it. The fixed points:

| Decision | Choice | Why |
| --- | --- | --- |
| Where | A method of a class, whether the class is generic or not. Not a constructor (TypeScript forbids type parameters there). Interfaces have no methods, so they are out. | Matches TypeScript, and adds nothing Nish has no layout for. |
| Scope | The class's parameters are in scope inside the method. A method parameter with the same name as a class parameter is refused (a new code, in NL2302's voice). | TypeScript allows shadowing. Nish refuses it because a diagnostic that names `T` must mean one thing. |
| Inference | From the arguments only, exactly as for a generic function (§2a). No explicit type arguments at the call. A parameter that cannot be inferred gets the generic function's refusal, naming the method. | Reuses the one inference path. |
| Key and symbol | One instantiation per (concrete receiver struct × method tuple). The symbol is the receiver's method symbol plus the function mangling of the method tuple (for example `Box$i32.pick$string`). The worker must prove it injective against every existing mangled form, and record it in §15.8. | Every instantiation gets one define, so there is still no boxing and no dictionary. |
| Display | `Box<i32>.pick<string>` in diagnostics and `-g` `name`. The mangled symbol goes in `linkageName`. | The display-names rule. |
| Termination | The request chain already covers function and struct requests. A method request joins it, so polymorphic recursion through a method is refused with the existing wording. | §4. |
| Constraints | `pick<U extends Shape>` works as for functions: member access by origin, and satisfaction at the request. | §15.6. |
| Whole program | A generic method of an exported class, instantiated from another module, is defined once in the class's module and declared elsewhere (the G7 rule). | §15.5. |
| Interop | An exported generic method's instantiations go through the interop stage's C and JS naming. If a sidecar cannot describe one, refuse it with a stable code rather than emit something wrong. The worker picks which, and records it. | §6.8. |
| self/ | Not used in `self/` (the rolling freeze). The bootstrap input and fixed point are unchanged. | CLAUDE.md |
