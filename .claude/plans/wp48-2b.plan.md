## Context

Stage 2a ([amritk/nish#1744](https://github.com/amritk/nish/pull/1744)) laid out an `implements Compact` class's links as `i32` offsets but left three things deferred, each marked in the source:

- [`src/tbaa.ts`](../../src/tbaa.ts) `buildStructNode` (≈ line 117): a link "is an i32 offset yet still gets the pointer scalar node here; no access is tagged through these struct-path nodes". So a link access carries no `!tbaa` today and may-aliases everything.
- [`src/debug.ts`](../../src/debug.ts) (≈ line 468): a link member is a plain `u32`, so a debugger shows the raw offset.
- No debugger pretty-printer exists; `tools/` does not exist yet.

The design is in [`docs/wp48-ref32-classes.md`](../../docs/wp48-ref32-classes.md) §3.2 (the two decode shapes), §4 (the TBAA and Debug info rows) and §6.

## TBAA

- A new scalar node `ref32`, child of the root, sibling of `i32` (not a child of it: an `i32` field store must not alias a link store). Interned lazily, so a program with no compact class emits no new metadata and its IR does not move by a byte.
- In `buildStructNode`, a field with `field.link` gets the `ref32` node at its compact offset (the 4-byte offset `computeLayout` gave it), not the pointer node.
- `fieldTbaa` returns a tag `!{base, ref32, i64 offset}` for a link. Every link load and store (the encode and decode in `loadField` / `storeField`, [`src/emit-classes.ts`](../../src/emit-classes.ts)) carries it, with the same exclusions as today (`--no-optimize-attributes`, interface or implementing class, `declare class` layout).
- Self-compile check: node numbering must stay deterministic across the seed-built and self-built compilers (the bootstrap fixed point).

## Debug info

The member is `DW_TAG_base_type`, `DW_ATE_unsigned`, 32 bits, named `ref32 <Class>` (for example `ref32 TNode`), one type per compact class, interned. Decoded locals stay ordinary pointers. Only compact classes are affected.

## Pretty-printers

`tools/gdb/nish_ref32.py` and `tools/lldb/nish_ref32.py` (exact names to the repo's filename rules, `scripts/check-filenames.mjs`):

- Match a value whose type name starts `ref32 `, take the class name from the rest, and look up `struct.<Class>` (the DWARF name 2a emits for the struct type; check it).
- Decode: zero-based (Linux) is `offset << 2` with 0 as null. Based (macOS) is `nish_ref_base + 4 * offset` with 0 as null, reading the `nish_ref_base` global. Pick the shape by whether the `nish_ref_base` symbol exists in the inferior, not by host platform.
- Show null as `null`, otherwise the decoded `struct.<Class> *` (so `p *node.next` and child expansion work).
- A header comment in each file says how to load it (`source` / `command script import`), and the guide repeats it.
- These read only the debugged process's memory through the debugger API; they are not a builtin, a `nish:` module or a runtime file, so no `docs/security/` record is required (confirm against `scripts/security-scope.mjs`'s surface).

## Tests

- **TBAA no-alias**: a new positive `tests/cases/compact_tbaa.ts` (golden `.ll`, `.out`, registered with `node tests/differential/goldens.js --update`) storing an `i32` field, then a link, then reading the `i32` field. The PR body shows the exact IR (CLAUDE.md: show the IR for every TS snippet a PR adds). Plus a `tests/run.js` check that `opt -O2` on that IR forwards the first `i32` value past the link store (no second load), which fails if the tags alias.
- **No IR moves without a compact class**: `node tests/nish-cmp.js` passes with no new `DECLARED` entry; any compact case's golden moves only in `!tbaa` metadata.
- **gdb**: a `tests/run.js` section compiles a compact list program with `-g`, runs `gdb -batch -nx -x <script>` where the script sources `tools/gdb/nish_ref32.py`, breaks after the list is built, and in gdb Python asserts the decoded link's field equals the expected value, calling `gdb.execute("quit 1")` on mismatch. The verdict is gdb's exit status only, never its message text (CLAUDE.md, `.claude/testing.md` → "Checks that spawn a process"). First establish whether gdb is on CI's `ubuntu-latest` image (a probe in the first push, read from the job log). Where gdb is absent (macOS shards) the check follows the repo's existing platform-gating pattern so it does not add a non-environmental skip to a shard's count. If gdb is not on the ubuntu runner either, do not edit `.github/` (CODEOWNERS); keep the check, gate it as above, and say so in the PR body.
- **Based shape**: if a Linux build can produce the based decode (e.g. the arguments in `tests/cases/compact_darwin.args`), exercise the gdb printer on it too; otherwise state in the PR body that the based path is untested natively and why.
- The lldb formatter is not required to have a CI test; if lldb is on the runner, a smoke check in the same shape is welcome.
