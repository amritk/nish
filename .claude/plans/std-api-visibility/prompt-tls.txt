## Lessons from wave 1 (read before marking anything)
- **Check the guide before every `@internal`.** A free function in the module reading a member does not make it internal. Grep docs/guide/, docs/AI.md, docs/cookbook/ and examples/ for the member name. Anything a guide page or an example shows a user calling or setting is API: public, untagged, fully documented. Wave 1 tagged `HttpRequest.methodIs` and `HandlerLimits.jsonBytes` `@internal`, and both are in the api-server guide page.
- **Treat a sibling family as one decision.** Methods like `i32Array`/`u64Array`/... or the fields of one limits object get the same visibility, unless a specific member has a specific reason, which you name.
- **Check every doc claim about units and lifetimes against the code.** For example, whether a limit counts raw or decoded bytes, or whether a config object is read once or kept by reference and read live. Wave 1 shipped one of each wrong.
- Put each `@internal` inside the JSDoc directly above the member it describes.
